# workbuddy2api 使用说明

把 **WorkBuddy / CodeBuddy**（腾讯代码助手）的账号，变成你本机可用的
**OpenAI / Anthropic 兼容 API**。

- 服务地址：`http://127.0.0.1:8787`
- 管理后台：`http://127.0.0.1:8787/admin/`
- 支持接口：`/v1/chat/completions`、`/v1/responses`、`/v1/messages`、`/v1/models`

---

## 一、三分钟上手

### 1. 启动

```powershell
D:\item\codebuddy2api\deploy-local\start-admin.bat
```

双击即可。看到 `✅ 监听 http://127.0.0.1:8787` 就是成功了。

> 启动日志里会打印**管理密钥**和**管理界面地址**，第一次请留意。

### 2. 登录后台

浏览器打开 <http://127.0.0.1:8787/admin/>，输入 `.env` 里的 `ADMIN_KEY`。

### 3. 拿到 Base URL 和 Key

后台左侧 **「接入指南」** 页一页就能看到全部：

| 项目 | 值 |
|------|-----|
| OpenAI / Responses Base URL | `http://127.0.0.1:8787/v1` |
| Anthropic Base URL | `http://127.0.0.1:8787` |
| API Key | 页面上直接显示，点「复制」 |

### 4. 填进你的客户端

**Codex CLI** —— 合并到 `~/.codex/config.toml`：

```toml
[model_providers.workbuddy]
name = "WorkBuddy"
base_url = "http://127.0.0.1:8787/v1"
wire_api = "responses"
env_key = "CODEBUDDY2OPENAI_KEY"

[profiles.workbuddy]
model = "deepseek-v4.1-flash"
model_provider = "workbuddy"
```

```powershell
$env:CODEBUDDY2OPENAI_KEY="后台显示的 Key"
codex --profile workbuddy "你的任务"
```

**Claude Code / CC Switch**：

```json
{
  "WorkBuddy": {
    "base_url": "http://127.0.0.1:8787/v1/messages",
    "api_key": "后台显示的 Key",
    "model": "deepseek-v4.1-flash"
  }
}
```

**Cherry Studio / LobeChat / NextChat / Open WebUI**：

- Base URL：`http://127.0.0.1:8787/v1`
- API Key：后台显示的 Key
- 模型名：见后台「模型与倍率」页

## 二、日常操作

| 我要做什么 | 怎么做 |
|-----------|--------|
| 启动服务 | `deploy-local\start-admin.bat`（双击） |
| 停止服务 | `deploy-local\stop.ps1` |
| 强制重启 | `deploy-local\start-admin.ps1 -Force` |

| 健康自检 | `deploy-local\check.ps1` |

| **让 /v1/models 只返回该账号模型** | 同上（会自动切到手动模式） |

> 只有 `start-admin` 才带管理后台。`start.bat` 是纯 API 模式（无后台、
> 不校验 Key），一般用不到。

## 三、管理后台

### 概览
账号、总积分、请求量、成功率、平均耗时、最近 100 条请求。

### 账号池
- **多账号轮转**：新请求自动分配，跳过暂停/冷却/积分耗尽的账号
- **手动指定**：固定用一个账号（`/v1/models` 会精确返回该账号的模型）
- 每个账号可：查询积分、签到、刷新凭据、暂停、删除

### 模型与倍率
- **各账号可用模型**：按账号显示它实际能用的模型
  - 点 **「探测未确认模型」** 可以主动发现目录外的可用模型
    （每次消耗极少额度，默认每批 8 个）
- **倍率表**：官方倍率 / 实际生效（含限时免费促销）/ 实测倍率
- **刷新上游目录**：立即重新拉取上游模型目录

### API 密钥
- **创建密钥**：新 Key 只显示一次，**创建后立刻复制保存**
- `.env` 里那个初始 Key 可以随时在「接入指南」页复制
- 撤销后立即停止接受新请求

### 连接测试
用当前账号真实发一条请求，验证模型能不能用。

### 接入指南
Base URL + API Key 集中展示，一键复制。

## 四、关于客户端 Key

### Key 存在哪里

| 位置 | 内容 | 能否修改 |
|------|------|---------|
| `deploy-local\.env` | `CODEBUDDY2OPENAI_KEY`（初始 Key） | ✅ 可改，但**只在首次启动时生效** |
| `deploy-local\management\state.json` | 所有 Key 的 **SHA-256 摘要** | ✅ 可改（推荐用脚本） |

**服务端只存摘要，不存明文** —— 所以后台无法还原完整 Key，
这是上游的安全设计。

### 这个 Key 必须存在吗？

**不是必须的。** 分两种情况：

| 情况 | 没有这个 Key 会怎样 |
|------|-------------------|
| **首次启动**（`state.json` 不存在） | 服务能正常启动，但**没有任何客户端 Key**，所有 `/v1/*` 请求都返回 401，需要去后台新建一个 |
| **已有 `state.json`** | 完全不影响。`.env` 里那个值会被**忽略**，Key 以 `state.json` 为准 |

实测验证：

```
首次启动 + 有 KEY  → 该 Key 可用
首次启动 + 无 KEY  → 服务正常启动，但无 Key（需后台新建）
已有 state.json + 改了 KEY  → 新值被忽略，旧 Key 仍有效
已有 state.json + 清空 KEY  → 旧 Key 仍有效
```

> **必须存在的是 `ADMIN_KEY`**（管理密钥），它不足 20 字符服务会直接启动失败。

### 怎么改 Key

**方式一：后台新建（最简单，推荐）**

「API 密钥」页 → 创建密钥 → **立刻复制保存**（只显示一次）。
旧的可以留着或撤销。

**方式二：改 `.env`（仅首次启动有效）**

```ini
# deploy-local\.env
CODEBUDDY2OPENAI_KEY=sk-wb-你的新Key
```

> ⚠️ **如果 `state.json` 已存在，改这里没用** —— 程序只在首次初始化时读取它。
> 想让改动生效，要么删掉 `management\state.json`（会重置后台，账号需重新导入），
> 要么用下面的方式三。

**方式三：用脚本改（推荐用于替换现有 Key）**

```powershell
deploy-local\set-key.ps1              # 自动生成新 Key 并替换
deploy-local\set-key.ps1 -List        # 只看当前有哪些 Key
deploy-local\set-key.ps1 -KeepOld     # 新增一个，保留旧的
deploy-local\set-key.ps1 -NewKey "sk-wb-自定义内容"
```

脚本会自动备份 `state.json`，改完**重启服务**生效。

### 为什么改 `.env` 不生效？

因为 Key 一旦初始化就存进 `state.json` 了，之后以它为准：

```
首次启动 → 读 .env 的 CODEBUDDY2OPENAI_KEY → 写入 state.json（存摘要）
再次启动 → state.json 已存在 → 直接用它，不再看 .env
```

这是上游的设计，避免每次重启都把 Key 重置回去。

## 五、关于模型

### ⚠️ 先看这条：模型列表取决于「请求分配」模式

`/v1/models` 返回什么，由**账号池的「请求分配」设置**决定：

| 请求分配 | `/v1/models` 返回 | 适用场景 |
|---------|------------------|---------|
| **手动指定账号** | **只有当前账号**的模型 | 想精确控制用哪个号（推荐） |
| 账号池轮转 | 所有轮转账号的**并集** | 想自动负载均衡 |

**如果你希望"用哪个号就返回哪个号的模型"，必须切到「手动指定账号」模式。**

切换方式（任选其一）：

- 后台「账号池」页 → 上方「请求分配」选 **手动指定账号** → 保存设置
- 或直接点某个账号行的 **「切换为此账号」**（会自动切模式并选中该账号）
- 或在「模型与倍率」→「各账号可用模型」里点 **「切换为此账号」**

> **为什么轮转模式要返回并集？**
> 因为轮转模式下请求会随机分到不同账号，无法预知某一个请求走哪个号。
> 这时返回并集是诚实的做法；返回某一个号的模型反而会误导你。

### 模型列表是按账号返回的

切到手动模式后，`/v1/models` 只返回**当前账号实际能用的模型**。

**每个账号的模型 = 该区域上游目录 + 实测确认可用 − 实测确认不可用。**

### 上游目录不完整，所以需要「实测」

上游返回的模型目录**并不完整**。实测国际账号：

| 模型 | 在上游目录里 | 实际能不能用 |
|------|------------|------------|
| `deepseek-v4.1-flash` | ❌ 没有 | ✅ **能用** |
| `glm-5.1` | ❌ 没有 | ✅ **能用** |
| `deepseek-v4-pro` | ❌ 没有 | ❌ 不能用 |

所以：**目录只当候选池，真实可用性靠实测**。

### 怎么让国际账号的 deepseek 出现

两种方式，任选：

1. **直接调用一次**——成功就自动记住，之后一直在列表里
2. **点「探测未确认模型」**——批量试探，一次能发现好几个

> 上游对不可用模型返回 `11102`，对限流返回 `429`。
> 只有 `11102` 才判定为「没有这个模型」；`429` 会标「未判定」，下次再探。

## 六、常见问题

### 接口报 401 `invalid api key`

管理后台模式强制校验 Key。用「接入指南」页显示的 Key。

### 看不到完整 Key / 复制不了

上游设计只保存密钥的 SHA-256 摘要，**除创建时的一次性显示外无法还原**。

- `.env` 里的初始 Key：本部署已开启 `ADMIN_REVEAL_INITIAL_KEY=1`，可在后台复制
- 后台新建的 Key：只能看一次，忘了就撤销重建一个

### 改了 `.env` 里的 Key 但不生效

正常现象。Key 一旦初始化就存进 `management\state.json` 了，之后不再读 `.env`。
改用 `set-key.ps1`，或直接在后台新建一个。详见第四节。

### 服务启动失败，报 `ADMIN_KEY must contain at least 20 characters`

`ADMIN_KEY`（管理密钥）是**必须**的，且至少 20 字符。
注意：客户端 Key（`CODEBUDDY2OPENAI_KEY`）不是必须的，别搞混。

### 报 429 `too many requests`

上游限流。账号池会自动冷却该账号 5 分钟。
也可以在账号行点「刷新凭据」立即解除。

### 报 `11102 model service info not found`

当前账号没有这个模型。系统会自动记住并把它从该账号列表移除。

### 报 `401 Authorization Required`

凭据和网关不匹配（国内/国际）。正常情况下会自动路由，
确认补丁已应用（`git diff` 应看到 `core/converter.py` 有改动）。

### 报 `11128 first message is not system prompt`

国际后端要求首条消息是 system。补丁已自动补占位。
如果你自己改 system prompt，避开「You are …」+ 厂商名的句式
（这种句子会被脱敏逻辑整句删除）。

### 服务起不来 / 端口被占用

启动脚本会自动检测并打印占用进程的 PID：

```powershell
deploy-local\stop.ps1            # 停掉旧服务
deploy-local\start-admin.ps1 -Force   # 或强制重启
```

### 双击 `start.bat` 闪退

本机控制台代码页是 **936(GBK)**，批处理必须存为 GBK 编码。
本目录的 `.bat` 已按 GBK 保存，**不要用 UTF-8 另存**。

|------|------|
